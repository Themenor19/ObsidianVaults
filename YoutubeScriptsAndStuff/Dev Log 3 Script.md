## Saving
I don't remember how much, if at all I touched saving in the last video. But I have 2 different forms of saves for the players since the last video. I had started out with saving all data as a json file. Such as storing the players last known position, a list of item id's and quantities representing the players inventory, player coins and player health. The great thing about this approach is that it's easy enough to do for a beginner, and it's just plaintext, so it's also easily editable for debugging. I did end up moving on from this however to a different form of saving that Godot provides, which is Binary. The main reason why I did this is because with JSON, if I wanted to store things such as a Vector2, I would have to manually write up a conversion from Vector2 to dict of 2 floats for x and y and store that instead. Essentially, json doesn't have direct support for Godot variables, but since the binary version was implemented by Godot, you can just directly save Godot variables such as vectors, and even whole scenes and resources. Only downside is you can't save self made objects without converting those objects into dictionary's of Godot variables...which I know sounds exactly like the problem that I had with JSON...BUT DON'T WORRY ABOUT IT!!! In all reality, it actually is better because it's a lot easier convert the classes into dictionaries for the binary version because all you have to do is just take the important information for the classes, and write a to dict and from dict function (or a save and load function) using the variable names as keys, and badabing, badaboom you're golden. It's easier for me to do, and a lot more consistent. And binary also adds the nice feature of being slightly smaller than JSON to my knowledge.
